# Эксплуатация

Для нового разработчика: [CONFIGURATION](CONFIGURATION.md) и [TESTING](TESTING.md).
Контракты API — в [API](API.md), состав данных и резервных копий — в
[DATA_MODEL](DATA_MODEL.md). Здесь описано обслуживание установленной системы.

## Установка с нуля

1. Python 3.14, Git, 7-Zip, Claude Code (вход в аккаунт с подпиской: `claude` → `/login`).
2. Код: `git clone https://github.com/shibanalex/Ubermensch_Project.git`, затем
   ```
   python -m venv .venv
   .venv\Scripts\pip install -r requirements.txt
   ```
3. `.env` по образцу `.env.example` (токен бота, chat_id, ключи Telegram API, Gmail, пароль бэкапов).
4. Данные: восстановить из бэкапа (см. ниже) или заранее создать `D:\Ubermensch\db`
   (при другом `UBERMENSCH_DATA` — `db` внутри него). Пустого корня недостаточно:
   стартовая проверка ждёт каталог `db` до загрузки настроек.
5. Вход в Telegram: `telegram_login.bat`; рабочий аккаунт (если задан `TG_WORK_API_ID`/`TG_WORK_HASH`) — `telegram_work_login.bat`.
6. Личный кабинет вуза: `LK_LOGIN`/`LK_PASSWORD` в `.env` (или ручной вход `lk_login.bat`).
7. Запуск: `start.bat`; автозапуск: `powershell -ExecutionPolicy Bypass -File scripts\install_autostart.ps1`.

### Дополнительно (рекомендуется)

- **Claude Code отдельно**: `irm https://claude.ai/install.ps1 | iex`, затем `claude` → `/login`. Ядро ищет программу так: `CLAUDE_BIN` → PATH → `%USERPROFILE%\.local\bin\claude.exe` → встроенная в расширение VS Code.
- **Everything** (voidtools) + `es.exe` в `D:\Ubermensch\bin\` — мгновенный поиск файлов. Everything должен быть запущен (Tools → Options → «Start Everything on system startup»). Без него поиск идёт медленным обходом папок.
- **KeePassXC** — хранить `BACKUP_PASSWORD` и ключи.

### Подключение Google Календаря (один раз)

1. console.cloud.google.com → создать проект (любое имя, например «Anya»).
2. «APIs & Services» → «Library» → **Google Calendar API** → Enable.
3. «OAuth consent screen» → External → заполнить имя и свою почту → в «Test users» добавить свой Gmail.
4. «Credentials» → «Create credentials» → **OAuth client ID** → тип **Desktop app** → Download JSON.
5. Сохранить файл как `D:\Ubermensch\secrets\google_oauth_client.json`.
6. Запустить `google_login.bat` → в браузере разрешить доступ к событиям календаря.

Доступ ограничен событиями календаря; отозвать — myaccount.google.com/permissions.

### Что понимает папка импорта

| Что положить | Как разбирается |
|---|---|
| Чат Google AI Studio (файл из Google Drive) | глубоко: целиком, без повторов, в память — только новое; сжатый конспект новых сведений — в Obsidian → «Конспекты». Повторить: `POST /api/import/deep` с `{"name": "<имя файла>"}` |
| PDF, Word (.docx), .txt, .md | целиком, как документ |
| Выгрузка ChatGPT или Claude.ai (`conversations.json` или zip с ним) | твои реплики → «Разговоры с ИИ», разбор по месяцам |
| Архивы Google Takeout (`takeout-*.zip`, все части) | «Мои действия» и история YouTube → по месяцам; твои комментарии и чаты трансляций YouTube; партитуры с Диска → «Творчество»; чаты AI Studio с Диска → глубокий импорт; подписки и плейлисты → документ. Видео, музыка, картинки, книги и Фото не читаются. Что выгружать: «Мои действия», YouTube, Диск, Chrome (почта уже собирается напрямую) |

Обычный импорт пропускает файл с тем же хешем и статусом done; skipped/failed
пробуются снова. Ручной deep import может повторно обработать уже известный файл.
Механизмы продолжения обычного и глубокого импорта различаются, см. [BACKGROUND](BACKGROUND.md).

## Состояние и диагностика

- **Telegram `/status`** — сервисы, расследование, известные проблемы.
- **Маскот** — `⚠` в строке состояния, если есть проблема; серый `x x` — нет связи с ядром.
- **Окно метрик** — ПКМ по маскоту (или трей, или лист задач) → «Метрики»: прогресс разбора и памяти, время за ПК, полезное/отвлекающее, задачи. F5 — обновить, Tab — вкладка.
- **API**: `GET /api/health` (проблемы + сервисы), `GET /api/investigation` (сбор и разбор), `POST /api/collect` (собрать сейчас), `POST /api/voice` (пересобрать стиль и голос Ани), `GET /api/metrics` (то же, что в окне метрик). Заголовок `Authorization: Bearer <токен из secrets\api_token>`.
- **Лог**: `D:\Ubermensch\logs\ubermensch.log`.

### Резервный ИИ и общий API инструментов

После обновления остановить ядро и запустить `start.bat`: уже работающий процесс сам код
не перечитывает. Дополнительный ключ не нужен: используется существующий `OPENAI_API_KEY`.
Модель `OPENAI_CHAT_MODEL` должна поддерживать Chat Completions, функции и JSON Schema.
Общие инструменты доступны через `GET /api/tools` и `POST /api/tools/call`
с заголовком `Authorization: Bearer <токен>`; тело вызова:
`{"name":"read_file","arguments":{"path":"C:/путь/заметка.txt"},"run_id":"<UUID>"}`.
`run_id` необязателен: без него ядро создаёт новый.

Лимит Claude до запуска инструментов переключает запрос на OpenAI. Если инструмент уже
начат или его результат неизвестен после сбоя, запрос автоматически не повторяется.
Проверить результат вручную, затем дать новую просьбу на оставшиеся действия.
Для диагностики использовать журнал попытки и основной лог. Журналы пока не очищаются
автоматически; это небольшие записи имён и статусов.

Проверки без внешних ИИ и реальных отправок:

```powershell
.venv\Scripts\python.exe -m unittest discover -s tests -v
```

## Известные ситуации и что делать

| Ситуация | Что видно | Что делает система | Что делать тебе |
|---|---|---|---|
| Лимит подписки Claude | Сообщение о лимите либо резервный ответ | До начала общих инструментов чат может перейти на доступный OpenAI. После начала автоматического повтора нет. Фоновая работа ждёт сброса; deep import имеет сохранённый прогресс частей, обычный импорт не даёт той же гарантии после рестарта | Проверить результат уже начатого действия; подробности в AI_RUNTIME и BACKGROUND |
| Перезапуск или сон посреди глубокого импорта | — | прогресс сохраняется после каждой части (курсор `distill:<хэш>`), импорт продолжается со следующей части | ничего |
| Порция не разобралась 3 раза подряд (сеть, сон) | в логе «не разобрана» | через 12 часов снова ставится в очередь | ничего |
| Claude разлогинился | «Claude разлогинился…» | не дёргает Claude 5 минут, потом проверяет снова; сообщает со второй неудачи подряд (первая после пробуждения обычно ложная — сеть ещё не поднялась) | терминал → `claude` → `/login` |
| Обновилось расширение VS Code / пропал Claude Code | «Не нахожу Claude Code» | ищет `claude.exe` заново при каждом вызове | установить Claude Code или обновить расширение |
| Завершена сессия Telegram | бот: «🔑 Нужен вход в … Telegram» | Аня сама начинает вход: спрашивает номер (или берёт `TG_PHONE`/`TG_WORK_PHONE` из `.env`), Telegram присылает код | прислать код в бота **с пробелами или дефисами** (`1 2 3 4 5` — целый код Telegram сбрасывает), при облачном пароле — его; бот удалит их из чата. | Отозван пароль Gmail | «Gmail не пускает…» | сбор почты пропускается | новый пароль приложения → `GMAIL_PASSWORD` в `.env` |
| D: заблокирован после перезагрузки | сообщение в Telegram «Диск заблокирован» | ядро ждёт и стартует само | открыть D: в Проводнике и ввести пароль BitLocker |
| Разбор днём медленный | ~4 порции в час | так задумано: лимит подписки общий с чатом и Claude Code; стоит отойти от ПК на 10+ минут или заблокировать экран (Win+L) — темп как ночью | ничего; хочешь быстрее — блокируй экран, когда уходишь |
| Ночь, а разбор стоит | в логе нет «Разобрано» с 01:00 до 08:00 | ночью разбор идёт быстро, но только пока ноутбук не спит | на ночь — на зарядку. От батареи закрытая крышка усыпляет, как обычно |
| Компьютер уснул | — | бот и сервисы замирают и продолжают после пробуждения; оборванный разбор повторяется до 3 раз | ничего |
| Не пускает в личный кабинет вуза | «Не могу войти в личный кабинет вуза…» | кабинет не читается, сайт вуза работает | проверить `LK_LOGIN`/`LK_PASSWORD` в `.env`; если капча — `lk_login.bat` и войти вручную |

## Резервные копии

- Каждую ночь (или днём, если ночью компьютер был выключен) — архив `anya-ГГГГ-ММ-ДД_ЧЧ-ММ.7z`: база, стиль переписки, голос Ани, досье. Шифрование AES-256, имена файлов скрыты. Пароль — `BACKUP_PASSWORD` в `.env`. **Храни пароль отдельно от ноутбука** — без него архив не открыть.
- Копия вне ноутбука: создай в корне флешки или внешнего диска папку `AnyaBackup` — при подключении туда скопируется свежий архив (хранится 14 последних).
- Точный состав: SQLite snapshot, `tg_style.md`, `anya_persona.md` и `dossier`.
- **Не входят:** `secrets` (Telegram/OAuth/ЛК/API-токен), `.env`, `raw/import`,
  Obsidian vault, `Documents/Аня`, `tg_style_work.md` и прочие файлы workspace.
  Для этих данных нужен отдельный план копирования/восстановления; архив приложения
  не является полной копией обоих хранилищ на D:.

### Восстановление

1. Подготовить окружение без запуска ядра. Если восстанавливается существующая
   установка, остановить именно её Core и автозапуск на время работ; сохранить
   текущий комплект данных, включая WAL/SHM. Не подменять базу в работающем процессе.
2. Распаковать архив в отдельный пустой каталог. Пример PowerShell:
   `& 'C:\Program Files\7-Zip\7z.exe' x 'anya-....7z' '-oD:\Ubermensch\restore'`.
   Ввести пароль интерактивно, проверить код выхода и состав распаковки.
3. На распакованном snapshot проверить `PRAGMA integrity_check` и `user_version`
   отдельным SQLite-подключением. Не открывать оригинал новым Store только ради
   диагностики: его конструктор применяет миграции.
4. Положить восстановленный `ubermensch.db` в каталог `db`, стили — в workspace,
   dossier — в корень DATA_DIR. Старые WAL/SHM от другой базы не оставлять рядом с
   восстановленной; сначала сохранить их с прежним комплектом.
5. Восстановить настройки `.env`, отдельно подключить нужные Telegram/OAuth/ЛК-сессии.
   Проверить независимые пути Obsidian и документов. Не входившие в архив файлы
   взять из их отдельных копий.
6. Запустить ядро, проверить `/api/health`, задачи и историю, затем desktop.
   Проверку реальной доставки выполнять отдельным явно выбранным тестовым действием.
