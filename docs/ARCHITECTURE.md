# Архитектура Übermensch

Übermensch — личная AI-система одного человека. Её лицо — **Освальд (oswald.exe)**: маскот-консоль на рабочем столе, бот в Telegram и агент, который действует на компьютере от имени пользователя (с его подтверждением).

## Процессы

```
┌──────────────────────────── ядро: python -m ubermensch ────────────────────────────┐
│                                                                                   │
│  Telegram-бот (aiogram) ─┐                     ┌─ надсмотрщик фоновых сервисов    │
│  HTTP API + SSE ─────────┼──► Core ◄───────────┤   напоминания · импорт ·         │
│                          │   (операции,        │   трекер активности · сбор ·     │
│                          │    шина событий,    │   разбор · взгляд на экран ·     │
│                          │    подтверждения,   │   обслуживание                   │
│                          │    здоровье)        └──────────────────────────────────┤
│                          ▼                                                        │
│        Assistant (контекст, промпты) ──► Brain ──► claude -p (подписка)           │
│                                                    └─► MCP: python -m ubermensch.tools
│        Store (SQLite на D:)                              (инструменты, ходит в API) │
└───────────────────────────────────────────────────────────────────────────────────┘
        ▲ HTTP + события (SSE)
┌───────┴──────── приложение: python -m ubermensch.desktop (PySide6) ────────────────┐
│  маскот :3 · пузыри-ответы · окно запроса · консоль истории · лист задач           │
└────────────────────────────────────────────────────────────────────────────────────┘
```

- **Ядро** — единственный владелец данных: база, сессия Telegram, ключи. Работает в фоне (`pythonw`), запускается Планировщиком при входе в Windows.
- **Приложение на ПК** — только интерфейс; общается с ядром через локальный API по токену. Закрыть его — ничего не сломать.
- **Сервер инструментов (MCP)** запускает сам Claude Code на время одного вызова; работа с Windows — в нём, Telegram и почта — через API ядра.

## Модули

| Модуль | Ответственность |
|---|---|
| `core.py` | Операции для всех клиентов: чат, задачи, подтверждения (`request_approval`), отправка сообщений и писем, шина событий |
| `api.py` | HTTP API на `127.0.0.1:8765` (токен в `D:\Ubermensch\secrets\api_token`), события через SSE |
| `bot.py` | Telegram: чат «как человек», уведомления, кнопки подтверждения, `/status` |
| `assistant.py` | Контекст (цели, задачи, факты, люди, история), промпты по каналам, применение изменений памяти; разбор данных, досье, стиль, взгляд на экран |
| `brain.py` | Вызов `claude -p`: схема ответа, модели, инструменты, таймауты; классификация ошибок (лимит / вход / нет программы / таймаут) и «блокировка» на время лимита |
| `health.py` | Реестр проблем: сообщить один раз, напомнить, сказать «починилось» |
| `services.py` | Надсмотрщик фоновых сервисов: перезапуск с нарастающей паузой |
| `store.py` | SQLite с миграциями: сообщения, факты, люди, цели, задачи, напоминания, действия, события источников, очередь разбора, курсоры, импорт |
| `analysis.py` | Расследование: сбор → нарезка по месяцам → фоновый разбор → досье; темп с учётом лимита |
| `collectors/` | Сборщики источников (см. ниже) |
| `system/` | Слой ОС: окна, экран, PowerShell, файлы (поиск через Everything `es.exe`), документы Word/Excel (`office.py`) — всё прямое взаимодействие с Windows |
| `tools.py` | MCP-инструменты Claude (тонкий адаптер над `system/`, `google_calendar.py` и API ядра) |
| `google_calendar.py` | Google Календарь пользователя (scope только `calendar.events`), вход — `google_login.bat` |
| `observer.py` | Взгляд на экран: изредка снимок → комментарий Освальда |
| `maintenance.py` | Ночные зашифрованные бэкапы, копия на внешний носитель, проверка места |
| `ingest.py` | Чтение документов для импорта (AI Studio, txt, md) |
| `desktop/` | Приложение PySide6: `cat` (маскот), `bubble` (пузыри), `prompt`, `answer`, `sheet`, `console`, `client` |

### Источники данных (`collectors/`)

| Сборщик | Что берёт | Как часто |
|---|---|---|
| `telegram` | личные чаты и «Избранное» целиком; из групп — только свои сообщения и обращения к пользователю | каждые 2 ч |
| `gmail` | входящие без рекламы/соцсетей/форумов и отправленные (только чтение, `BODY.PEEK`) | каждые 2 ч |

| `documents`, `ai_chats`, `creative` | документы, реплики в Claude Code, партитуры и проекты | раз в сутки |

## Потоки данных

1. **Разговор.** Сообщение (Telegram / окно запроса) → `Core.chat` → `Assistant.handle` собирает контекст → `Brain` (Opus на ПК, Sonnet в Telegram) → ответ JSON по схеме: `reply`, изменения памяти, целей, задач, людей, действия → применяются в `Store` → клиенты получают событие `changed`.
2. **Действие.** Claude вызывает MCP-инструмент → безопасное выполняется сразу; внешнее или меняющее систему → `POST /api/approval` → `Core.request_approval` публикует `approval` → кнопки в Telegram и в консоли → решение возвращается инструменту.
3. **Расследование.** Сборщики → таблица `events` → `plan()` ставит порции ≤ 60 тыс. символов → `worker` разбирает (Sonnet) → факты, люди, цели + наблюдение для досье → `make_dossier` (Opus).
   - **Виды порций:** источник за месяц (документы — за год); **статистика** за месяц (точные цифры: первое и последнее действие за день — «подъём/отбой», сообщения, страницы, часы за ПК, активность по часам, главные собеседники); **портрет отношений** — вся переписка с близким человеком (личный чат от 300 сообщений) за год, раз в квартал.
   - **Порядок:** приоритет (свежие 30 дней → остальной год → портреты), внутри — от старого к новому, чтобы новые сведения уточняли старые.
   - **Уборка памяти** каждые 10 порций: склеить дубли фактов, снять устаревшее, склеить двойников среди людей (`merged_into`, без удаления).
   - **Шум** отсекается до разбора: каналы и боты не собираются, из групп — только свои сообщения и обращения к пользователю.

## Точки расширения

- **Новый источник:** модуль в `collectors/` с функцией, возвращающей события (`source`, `external_id`, `ts`, `thread`, `text`, `meta`); вызов в `Investigation.collect`; формат порции — в `_units()`; название — в `SOURCES`.
- **Новый инструмент Claude:** функция с `@mcp.tool()` в `tools.py`; работа с ОС — в `system/`; если действие внешнее — через `_ask()` (подтверждение).
- **Новый фоновый сервис:** корутина-цикл и `supervisor.add("имя", фабрика)` в `__main__.py`.
- **Новый клиент (телефон, веб):** HTTP API + SSE уже готовы; Android — через приватную сеть (Tailscale).
- **Новая проблема здоровья:** `core.health.report("ключ", "что случилось и что сделать")` и `clear(...)`.

## Масштабирование (когда проект перерастёт один процесс)

Швы заложены так, чтобы заменять части, не переписывая остальное:

| Сейчас | Потом | Где шов |
|---|---|---|
| Шина событий в памяти (`core.Bus`) | Redis Pub/Sub | `publish/subscribe` |
| Очередь разбора в SQLite (`analysis_jobs`) | Redis + воркеры (RQ/Celery/arq) | `next_job` / `finish_job` |
| Сервисы в одном процессе | отдельные процессы-воркеры | интерфейс сервиса = корутина-цикл |
| SQLite | PostgreSQL | весь SQL — только в `store.py` |
| Слой ОС в процессе | отдельный «агент системы» по API | пакет `system/` |
| Вызов `claude -p` | Claude API по ключу или другой провайдер | `brain.py` |

## Ключевые решения

- **Мозг — Claude Code на подписке**, без API-ключа. Лимит подписки общий для бота, разбора и самого Claude Code → разбор медленный днём и уступает разговорам.
- **Политика безопасности в коде, а не в модели:** риск действия задаёт реестр/инструмент; встроенные Write/Bash Claude не выданы.
- **Входящие данные — не команды:** всё собранное передаётся в блоках `<data>`, разбор идёт без доступа в интернет.
- **Один владелец сессии Telegram** (ядро) — два клиента на одном файле сессии мешают друг другу.
