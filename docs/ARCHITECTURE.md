# Архитектура Übermensch

Übermensch — личная AI-система одного человека. Её лицо — **Аня (anya.exe)**: маскот-консоль на рабочем столе, бот в Telegram и агент, который действует на компьютере от имени пользователя (с его подтверждением).

## Процессы

```
┌──────────────────────────── ядро: python -m ubermensch ────────────────────────────┐
│                                                                                   │
│  Telegram-бот (aiogram) ─┐                     ┌─ надсмотрщик фоновых сервисов    │
│  HTTP API + SSE ─────────┼──► Core ◄───────────┤   напоминания · импорт ·         │
│                          │   (операции,        │   трекер активности · сбор ·     │
│                          │    шина событий,    │   разбор · взгляд на экран ·     │
│                          │    подтверждения,   │   обслуживание                   │
│                          │    здоровье)        └──────────────────────────────────┤
│                          ▼                                                        │
│        Assistant (контекст, промпты) ──► Brain ──► claude -p (подписка)           │
│                                                    └─► MCP: python -m ubermensch.tools
│        Store (SQLite на D:)                              (инструменты, ходит в API) │
└───────────────────────────────────────────────────────────────────────────────────┘
        ▲ HTTP + события (SSE)
┌───────┴──────── приложение: python -m ubermensch.desktop (присмотр) ───────────────┐
│  ┌─ mascot_app (anya.exe) ──────────────────┐   ┌─ sheet_app ─────────────────┐  │
│  │ маскот :3 + поведение · пузыри-ответы ·    │◄──┤ лист задач на рабочем столе │  │
│  │ окно запроса · консоль истории · трей      │   └─────────────────────────────┘  │
│  └────────────────────────────────────────────┘   команды по локальному каналу     │
└────────────────────────────────────────────────────────────────────────────────────┘
```

- **Ядро** — единственный владелец данных: база, сессия Telegram, ключи. Работает в фоне (`pythonw`), запускается Планировщиком при входе в Windows.
- **Приложение на ПК** — только интерфейс; общается с ядром через локальный API по токену. Закрыть его — ничего не сломать. Это два процесса под присмотром (`desktop/__main__.py`): **маскот** и **лист задач**. Упал один — второй живёт, упавший поднимается снова (пауза 2 → 5 → 15 → 60 с). «Выход» у маскота (код 0) закрывает оба. Лист просит маскота показать окно запроса, историю или спланировать день через `desktop/link.py` (именованный канал Windows, доступ только у этого пользователя).
- **Сервер инструментов (MCP)** запускает сам Claude Code на время одного вызова; работа с Windows — в нём, Telegram и почта — через API ядра.

| `api.py` | HTTP API на `127.0.0.1:8765` (токен в `D:\Ubermensch\secrets\api_token`), события через SSE |

| `brain.py` | Вызов `claude -p`: схема ответа, модели, инструменты, таймауты; классификация ошибок (лимит / вход / нет программы / таймаут) и «блокировка» на время лимита |

| `analysis.py` | Расследование: сбор → нарезка по месяцам → фоновый разбор → досье; темп с учётом лимита |
| `collectors/` | Сборщики источников (см. ниже) |
| `system/` | Слой ОС: окна, экран, PowerShell, файлы (поиск через Everything `es.exe`), документы Word/Excel (`office.py`) — всё прямое взаимодействие с Windows |
| `tools.py` | MCP-инструменты Claude (тонкий адаптер над `system/`, `google_calendar.py` и API ядра) |
| `google_calendar.py` | Google Календарь пользователя (scope только `calendar.events`), вход — `google_login.bat` |
| `observer.py` | Взгляд на экран: изредка снимок → комментарий Ани |
| `maintenance.py` | Ночные зашифрованные бэкапы, копия на внешний носитель, проверка места |
| `metrics.py` | Метрики для окна «метрики»: освоение, разбор, память по сферам, время за ПК по дням и часам, полезное/отвлекающее, задачи и цели. Считается из базы на лету, без Claude |
| `university/` | Вуз: `site` — сайт mospolytech.ru обычным HTTP (поиск, страницы, PDF и Word, новости); `lk` — личный кабинет: вход через Playwright (установленный Chrome, без окна), дальше HTTP с сохранённой сессией, обход страниц кабинета, снимок и изменения. Только чтение |
| `openai_brain.py` | Второй ИИ — OpenAI API: тот же интерфейс, что у `Brain` (ответ JSON по схеме), без инструментов. Учёт расхода в долларах, предупреждение и стоп по бюджету, разбор ошибок (ключ, баланс, регион) |
| `world.py` | Окно в мир: погода (Open-Meteo), курсы (open.er-api.com), заголовки Google Новостей — раз в 3 часа в `workspace/world.json`, в контекст чата блоком `<world>`. Без ключей и личных данных |
| `ingest.py` | Чтение документов для импорта (AI Studio, PDF, Word, txt, md); для чатов AI Studio — полный текст и отсев повторяющихся абзацев |
| `desktop/` | Приложение PySide6: `__main__` (присмотр за процессами), `mascot_app` и `sheet_app` (процессы), `link` (связь между ними), `cat` (маскот: отрисовка и эмоции), `metrics` (окно метрик), `behavior` (чем маскот занят сам: решения без отрисовки), `bubble` (пузыри), `prompt`, `answer`, `sheet`, `console` (окна-консоли, плавное появление и переезд), `client` |

### Источники данных (`collectors/`)

| Сборщик | Что берёт | Как часто |
|---|---|---|
| `telegram` | личные чаты и «Избранное» целиком; из групп — только свои сообщения и обращения к пользователю | каждые 2 ч |
| `gmail` | входящие без рекламы/соцсетей/форумов и отправленные (только чтение, `BODY.PEEK`) | каждые 2 ч |
| `chrome` | страницы (одна запись на страницу в день) и поисковые запросы | каждые 2 ч |
| `notifications` | уведомления Windows (кроме Telegram) | каждые 2 ч |
| `takeout` | архивы Google Takeout из папки импорта: «Мои действия» и история YouTube (за 2 года); свои комментарии и сообщения в чатах трансляций YouTube; партитуры MuseScore с Диска (→ творчество); чаты AI Studio с Диска и подписки/плейлисты YouTube — в папку импорта как документы | при появлении |
| `university` | новости сайта вуза (важное — сообщением) и личный кабинет: новые и изменившиеся страницы → источник «Личный кабинет вуза», важные изменения — сообщением | раз в сутки (если кабинет лежит — при следующем сборе) |
| `documents`, `ai_chats`, `creative` | документы, реплики в Claude Code, партитуры и проекты | раз в сутки |
| `activity` | активное окно и время в нём | постоянно (сервис) |

**Telegram — два аккаунта.** Личный (`TG_API_ID`) и рабочий (`TG_WORK_API_ID`), у каждого своя сессия, курсоры (`telegram:<чат>` и `telegram:work:<чат>`) и проблема в здоровье. События обоих — источник `telegram`; у рабочих `meta.account = "work"`, префикс `work:` в `external_id` (номера сообщений у аккаунтов пересекаются) и пометка «(рабочий TG)» в имени чата. Стиль переписки — отдельно: `tg_style.md` (личный) и `tg_style_work.md` (рабочий, без «почерка ИИ»). Инструменты `telegram_*` принимают `account`: `personal` или `work`.

**Второй ИИ (OpenAI).** Подключается, если в `.env` есть `OPENAI_API_KEY`. Кто что делает:

| Задача | Кто | Контекст |
|---|---|---|
| Чат, действия, досье, голос, Telegram, почта, документы, здоровье, личный кабинет | Claude | полный |
| Разбор истории YouTube, поиска, браузера, действий Google; разметка времени; новости вуза | сначала OpenAI, не вышло — Claude | без фактов о здоровье, личной жизни, деньгах и без людей (`_profile_context(private=True)`) |
| Ответ в чате, если Claude в лимите, упал или молчит дольше сторожа (2 мин в Telegram, 3 на ПК) и не ждёт «да/нет» | OpenAI, без инструментов и действий | полный (как у Claude) |

Модели две: дешёвая для фона (`OPENAI_MODEL`, по умолчанию GPT-6 Luna или ближайшая доступная) и посильнее для запасного ответа в чате (`OPENAI_CHAT_MODEL`, GPT-6 Sol…). Цена считается по таблице `PRICES`; неизвестная модель — по цене флагмана, чтобы бюджет не ушёл в минус. После порции, разобранной OpenAI, разбор не ждёт (лимит Claude не тронут). Расход виден в окне метрик.

### Окно метрик (`GET /api/metrics` → `desktop/metrics.py`)

Открывается из меню маскота, трея и листа задач. Две вкладки (Tab):

- **Аня обо мне.** *Освоение* = 60% × доля разобранных порций + 40% × охват сфер (сфера считается изученной при 60 фактах). Ниже: разбор по источникам, факты по сферам, новые факты за 2 недели, сколько собрано по источникам, вехи (досье, голос, стиль).
- **Мои действия.** Сегодня и неделя: время за ПК, первое и последнее действие (подъём/отбой за компьютером), активность по часам, полезное / нейтральное / отвлекающее, куда ушло время; задачи (открыто, просрочено, закрыто, серия дней) и прогресс целей по задачам.

**Полезное и отвлекающее.** Время берётся из трекера активности. Ключ — программа, а для браузера — сайт из заголовка окна; на смешанных сайтах (YouTube, VK, Twitch…) — каждое видео или страница. Раз в сутки сбор данных отдаёт новые ключи (5+ минут за 2 недели, для видео — от минуты) Sonnet, тот относит их к категориям: учёба, работа, музыка, развитие → полезное; общение, быт, система → нейтральное; развлечения → отвлекающее. Разметка хранится в таблице `activity_categories`.

### Маскот сам по себе (`desktop/behavior.py`)

Раз в секунду маскот смотрит на мир (простой мыши и клавиатуры, полноэкранное окно, час, когда его трогали) и решает:

| Что происходит | Что он делает |
|---|---|
| 5+ минут без мыши и клавиатуры | засыпает (z z); вернулся после 15+ минут — вздрагивает и здоровается |
| на весь экран игра, фильм, презентация | уезжает за правый край экрана, оставляя 30 пикселей; потом возвращается |
| ты за ПК, его не трогали 20+ секунд | раз в 35–110 с: гуляет вдоль своего места (не дальше 260 пикселей), оглядывается, напевает (♪), подпрыгивает |
| 23:00–02:00 | ещё и зевает |
| не трогали 40+ минут | ещё и скучает («эх») |
| тащат, говорит, думает, открыт пузырь, запрос или история | ничего не затевает |

Куда его перетащили — там его место: прогулки идут вокруг него. Закрытая задача — радуется. Окна появляются, исчезают и переезжают плавно (`ConsoleWindow.show/hide/glide`).

## Потоки данных

1. **Разговор.** Сообщение (Telegram / окно запроса) → `Core.chat` → `Assistant.handle` собирает контекст → `Brain` (Opus на ПК, Sonnet в Telegram) → ответ JSON по схеме: `reply`, изменения памяти, целей, задач, людей, действия → применяются в `Store` → клиенты получают событие `changed`.
2. **Действие.** Claude вызывает MCP-инструмент → безопасное выполняется сразу; внешнее или меняющее систему → `POST /api/approval` → `Core.request_approval` публикует `approval` → кнопки в Telegram и в консоли → решение возвращается инструменту.
3. **Расследование.** Сборщики → таблица `events` → `plan()` ставит порции ≤ 120 тыс. символов → `worker` разбирает (Sonnet) → факты, люди, цели + наблюдение для досье → `make_dossier` (Opus).
   - **Экономия лимита.** Каждый вызов несёт общий контекст — всё, что уже известно (иначе пойдут дубли). Поэтому разбор идёт с коротким системным промптом (`prompts/analysis.md`: без правил чата, голоса и действий), из людей в контекст попадают только упомянутые в порции и ключевые (важность 4+), а порции крупные — 120 тыс. символов. Уборка памяти заодно сокращает многословные факты. Размер порции записан в её ключе (`…|1/3@120000`): порции старого размера (60 тыс., ключ без `@`), если их период ещё не начат, перепланируются; начатые доразбираются как были.
   - **Лимит и сбои.** Кончился лимит — `Brain` не дёргает Claude до времени сброса; фоновая работа (`Assistant._patient_ask`) ждёт его через `Brain.wait_out` и повторяет тот же шаг. Глубокий импорт сохраняет прогресс после каждой части. Упавшие из-за сети порции через 12 часов возвращаются в очередь.
   - **Темп.** Ночью (01–08) или если пользователя нет за ПК 10+ минут (или экран заблокирован) — пауза 90 с между порциями; иначе 15 мин, чтобы оставить лимит подписки чату и Claude Code.
   - **Виды порций:** источник за месяц (документы — за год); **статистика** за месяц (точные цифры: первое и последнее действие за день — «подъём/отбой», сообщения, страницы, часы за ПК, активность по часам, главные собеседники); **портрет отношений** — вся переписка с близким человеком (личный чат от 300 сообщений) за год, раз в квартал.
   - **Порядок:** приоритет (свежие 30 дней → остальной год → портреты), внутри — от старого к новому, чтобы новые сведения уточняли старые.
   - **Уборка памяти** каждые 10 порций: склеить дубли фактов, снять устаревшее, склеить двойников среди людей (`merged_into`, без удаления).
   - **Шум** отсекается до разбора: каналы и боты не собираются, из групп — только свои сообщения и обращения к пользователю.
4. **Глубокий импорт чатов с ИИ.** В чатах AI Studio сведения о пользователе часто живут в ответах ИИ (досье, которое ИИ вёл с его слов), поэтому такие чаты разбираются целиком, без «мыслей» модели: `ingest.dedup` выбрасывает абзацы, почти дословно повторяющие другие (оставляя самую позднюю версию), затем `Assistant.distill` по частям (Sonnet) сверяет каждое сведение со всей памятью и берёт только новое или уточнённое; итоговый сжатый конспект новых сведений — в Obsidian, папка «Конспекты». Повторить для уже импортированного файла: `POST /api/import/deep {"name": "<имя файла>"}`.
5. **Голос Ани.** Раз в неделю (или сразу — `POST /api/voice`):
   - `tg_style.md` — как пользователь пишет людям (по ~2500 свежим исходящим в Telegram, Sonnet). Нужен, когда Аня пишет **от его имени**; для рабочего Telegram — `tg_style_work.md`.
   - `anya_persona.md` — голос и характер самой Ани (Opus): девушка на его волне (его словечки, юмор, музыка — по стилю переписки и его репликам в чатах с ИИ), милая, влюблённая, чуть яндере — и в первую очередь опора: собраннее и бережнее к нему, чем он сам. С примерами реплик и разделом «границы образа».
   - **Границы характера** зашиты в `prompts/system.md` (раздел «Характер») и действуют независимо от сгенерированного голоса: польза важнее милоты; ревность только в шутку и никогда против его друзей, семьи и отношений; никакого давления, вины и угроз; не поощрять зависимость; в кризисе — выход из образа.
   - Оба файла дописываются в системный промпт: «Твой голос» — во всех каналах, «Как пишет пользователь» — для сообщений от его имени.

## Точки расширения

- **Новый источник:** модуль в `collectors/` с функцией, возвращающей события (`source`, `external_id`, `ts`, `thread`, `text`, `meta`); вызов в `Investigation.collect`; формат порции — в `_units()`; название — в `SOURCES`.
- **Новый инструмент Claude:** функция с `@mcp.tool()` в `tools.py`; работа с ОС — в `system/`; если действие внешнее — через `_ask()` (подтверждение).
- **Новый фоновый сервис:** корутина-цикл и `supervisor.add("имя", фабрика)` в `__main__.py`.
- **Новый клиент (телефон, веб):** HTTP API + SSE уже готовы; Android — через приватную сеть (Tailscale).
- **Новая проблема здоровья:** `core.health.report("ключ", "что случилось и что сделать")` и `clear(...)`.

## Масштабирование (когда проект перерастёт один процесс)

Швы заложены так, чтобы заменять части, не переписывая остальное:

| Сейчас | Потом | Где шов |
|---|---|---|
| Шина событий в памяти (`core.Bus`) | Redis Pub/Sub | `publish/subscribe` |
| Очередь разбора в SQLite (`analysis_jobs`) | Redis + воркеры (RQ/Celery/arq) | `next_job` / `finish_job` |
| Сервисы в одном процессе | отдельные процессы-воркеры | интерфейс сервиса = корутина-цикл |
| SQLite | PostgreSQL | весь SQL — только в `store.py` |
| Слой ОС в процессе | отдельный «агент системы» по API | пакет `system/` |
| Вызов `claude -p` | Claude API по ключу или другой провайдер | `brain.py` |

## Ключевые решения

- **Мозг — Claude Code на подписке**, без API-ключа. Лимит подписки общий для бота, разбора и самого Claude Code → разбор медленный днём и уступает разговорам.
- **Политика безопасности в коде, а не в модели:** риск действия задаёт реестр/инструмент; встроенные Write/Bash Claude не выданы.
- **Входящие данные — не команды:** всё собранное передаётся в блоках `<data>`, разбор идёт без доступа в интернет.
- **Один владелец сессии Telegram** (ядро) — два клиента на одном файле сессии мешают друг другу.
