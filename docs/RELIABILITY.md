# Надёжность, права и качество помощи

Реализовано 23 октября 2026 года в существующем ядре, без LangChain/LangGraph.
Миграции применятся при следующем запуске Core. Рабочие данные при разработке не менялись.

## Проверка данных и транзакции

`contracts.py` содержит строгие Pydantic-модели HTTP и операций памяти. Строка
`"false"`, числа вместо текста, невозможные даты, отсутствующие обязательные поля
операций отклоняются до записи. Ошибки HTTP возвращают 400 и имена полей без
содержимого личных данных. Аргументы инструментов также используют strict=True.

`Assistant._apply_answer` проверяет все команды, затем применяет их внутри
`Store.transaction()` (вложенные SAVEPOINT). Факты, цели, задачи, люди и локальные
напоминания одного ответа сохраняются вместе. В чате сообщение assistant и notes
входят в ту же транзакцию; пользовательское сообщение записывается до вызова ИИ.
В deep import прогресс части сохраняется вместе с её результатами.
Транзакция не удерживается во время сетевого запроса.

Tools исполняются до финального ответа модели и имеют отдельный журнал: откат
памяти не отменяет уже отправленное письмо. Поля report/lessons не являются
командами БД; локальная проверка не оценивает качество текста.
`PRAGMA foreign_keys=ON` включён; исторические нарушения не исправляются молча.
PATCH задачи отличает отсутствующее поле от `due: null` и `notes: ""` (очистка).

## Вызовы и подтверждения

Миграция 7 добавляет `runs`, `tool_calls`, `deliveries`, `quality_feedback` и
`actions.call_id/expires_at/approval_hash`. Время новых сущностей — ISO 8601 UTC;
старые таблицы сохраняют прежний локальный формат.

`POST /api/tools/call` принимает UUID `call_id` и `run_id`; ответ — `{result, call_id}`.
Повтор завершённого call_id возвращает сохранённый результат, одновременный повтор
ждёт тот же вызов. Другие аргументы/имя/явно другой run_id с этим call_id отклоняются.
Ошибка после начала или незавершённый вызов при рестарте получает uncertain:
автоматического повтора нет. Без call_id создаётся новый вызов. Одинаковые по смыслу
запросы с разными ID не дедуплицируются. Gateway сообщает call_id при обрыве.

Состояние/результат: `GET /api/tool-calls/{id}`. Аргументы и результаты сохраняются
в личной SQLite и входят в зашифрованный бэкап: в них могут быть сообщения и файлы.
JSONL по-прежнему содержит только имя/статус; ротации записей SQLite пока нет.

Подтверждение связано с call_id, хешем аргументов, точным текстом и версией политики;
срок — 10 минут. После рестарта возобновляются только ожидающие операции из
`RESUMABLE`, у которых до барьера подтверждения не было эффекта. Подготовка/чтение
повторяются, хеш сверяется перед эффектом. При изменении подготовки повышать версию
политики. Старые approval без call_id отклоняются. Неопределённый эффект не повторяется.

## Доставка

`Core.notify` и напоминания создают доставки для Telegram и desktop. Telegram
подтверждается после успешного ответа API, ошибки повторяются с backoff 5 секунд —
1 час. Desktop получает очередь в `/api/state`, показывает событие и вызывает
`POST /api/deliveries/{id}/ack`. Напоминание становится sent после обоих каналов;
отключённый desktop может оставлять его pending после доставки в Telegram.
Отмена напоминания отменяет ещё не доставленные записи.

Повторы возможны при сбое между отправкой и записью подтверждения, в том числе
при частичной отправке длинного сообщения. Общей транзакции Telegram/SQLite нет.
Подтверждение desktop означает обработку клиентом, а не прочтение человеком.

## Длительные задания и API

| Маршрут | Контракт |
|---|---|
| POST `/api/runs/chat` | `{text, run_id}`; 202 и задание |
| POST `/api/runs/onboard` | `{run_id}`; 202, первоначальный разговор |
| GET `/api/runs` | До 30 заданий, активные первыми; полный результат запрашивается по ID |
| GET `/api/runs/{id}` | Статус, результат, ошибка, список вызовов |
| POST `/api/runs/{id}/cancel` | Остановка задания и его активных вызовов |
| POST `/api/collect`, `/api/voice`, `/api/import/deep`, `/api/agent/heartbeat`, `/api/profile/rebuild` | 202, `{started: true, run: {...}}` |
| POST `/api/feedback` | `{message_id, rating, note?}` либо `{run_id, rating, note?}` |

ID в URL — 32 hex-символа, как в ответе API. Старые `/api/chat` и `/api/onboard`
сохранены. Qt использует новые задания, короткие запросы и опрос состояния раз в
2 секунды независимо от SSE. Повтор отправки чата использует прежний run_id.
В истории есть состояние, результат, остановка и оценка последнего ответа.

Статусы: queued, running, waiting_approval, completed, failed, interrupted,
cancelling, cancelled. Разрыв HTTP не отменяет работу. При старте queued
возобновляются, running становятся interrupted: весь сценарий с возможными
эффектами не повторяется. Подтверждение инструмента можно завершить отдельно;
это не восстанавливает прерванный разговор ИИ. Поручения `agent/tasks.json` после
сбоя также interrupted. Для оставшейся работы нужно новое явное поручение.

Отмена останавливает дальнейшие шаги и процессы shell. Уже выполненное сохраняется;
внешний синхронный вызов через asyncio.to_thread может завершиться после отмены
ожидания. Такой результат uncertain требует сверки. SSE не имеет replay;
snapshot и outbox восстанавливают состояние и уведомления.

## Резервные копии

`backups.py` создаёт manifest версии 1 с SHA-256 каждого файла:

- `data/db/ubermensch.db` — SQLite backup, включая новые журналы и доставку;
- `data/raw`, `data/agent`, `data/personalization`, `data/dossier`, `data/workspace`;
- `documents` — ANYA_DOCUMENTS; `vault` — весь настроенный Obsidian;
- `reports` — отдельная OUTPUT_DIR, если она не входит в предыдущие зоны.

Secrets, .env, Telegram sessions, ссылки и служебные каталоги исключены. Пропуски
ссылок и отсутствие необязательного корня отражаются в manifest. Нужны отдельное
сохранение настроек и повторная авторизация интеграций. Это не образ домашней папки.
SQLite согласован внутри snapshot; общего атомарного снимка БД и внешних файлов
нет. Изменение файла во время копирования обнаруживается.

Внутри зашифрованного 7z лежит snapshot.tar. Пароль передаётся через stdin.
Архив становится готовым после пробной распаковки, сравнения manifest,
SQLite integrity_check и foreign_key_check. Только затем удаляются старые копии.
Внешняя копия проверяется по хешу до переименования.

```bash
.venv/bin/python -m ubermensch.backups verify /path/to/anya-....7z
.venv/bin/python -m ubermensch.backups restore /path/to/anya-....7z --to /path/to/new-restore
```

Каталог назначения должен отсутствовать. Команда не меняет живые DATA_DIR/Obsidian.
Для переключения остановить Core, сохранить прежние данные, перенести data/ в
DATA_DIR, vault/ и documents/ — в выбранные пути, настроить секреты, запустить Core.
Старые архивы без manifest восстанавливаются вручную; новая команда их отклоняет.

## Права

Режим interactive/background задаёт ядро в сохранённом run, не аргументы модели.
Фон имеет явный список инструментов: чтение, поиск, подготовка файлов, свои
поручения/навыки. Shell, отправка сообщений, управление компьютером и изменение
календаря запрещены. Встроенные Read/Glob/Grep у фонового Claude отключены.
В интерактивном Claude они остаются доступны: правила общих файловых инструментов
не являются sandbox для всего интерактивного Claude Code.

| Переменная | По умолчанию |
|---|---|
| UBERMENSCH_READ_ROOTS | Личные папки, дополнительные диски, Obsidian, зоны Ани |
| UBERMENSCH_WRITE_ROOTS | Личные папки и свободные зоны Ани |
| UBERMENSCH_BACKGROUND_WRITE_ROOTS | Документы Ани, отчёты, workspace/artifacts |
| UBERMENSCH_SHELL_MODE | confirm; disabled запрещает shell |

Пути разделяются `:`; пустой список действительно пуст. Проверяется resolve(),
включая ссылки. Вне зон интерактивный файловый инструмент требует подтверждения,
фоновый отказывает. Secrets/.env/.ssh/.gnupg исключены из read allowlist.

`run_shell(command, reason, mode='sandbox')` использует bubblewrap без сети,
с runtime /usr и записываемой workspace/shell. При отсутствии/ошибке bwrap нет
перехода к host. `mode='host'` без подтверждения выполняет только `shell.runs_on_host_freely`:
каждая часть цепочки из SAFE_HOST_COMMANDS (kwriteconfig6, qdbus6, wpctl, playerctl, ls, grep,
journalctl…), без перенаправлений, подстановок, одиночного `&`, `find -exec/-delete`, меняющих
подкоманд systemctl/loginctl/nmcli, выхода из сеанса, упоминаний секретов, системных папок и кода
Ани. Остальные команды требуют подтверждения точного текста.
Окружение не содержит API-ключей и startup hooks; это не ограничивает подтверждённый
host-shell в чтении файлов. shell.is_dangerous больше не решает вопрос доступа.
Проверки путей не защищают от другого процесса того же пользователя, меняющего
ссылки между проверкой и открытием.

## Подбор памяти и качество

Миграция 8 создаёт facts_fts и триггеры. В чате сначала выбираются подходящие
активные факты, затем добавляются важные/свежие. Запрос сводится к основам слов
([`recall.py`](../ubermensch/recall.py): Snowball для русского и английского, длинные основы
короче на букву, двухбуквенные латинские сокращения вроде hh/cv сохраняются) и ищется по
началу слова: «общежитием» находит «в общежитии». Синонимы и пересказ не ловятся — embeddings
не подключены, пока нет измеримой пользы.

В контекст разговора идёт и `<related_experience>`: прошлые шаги по целям (что делала, итог,
что мешало), советы с его решением и эксперименты с выводом по тем же основам слов — чтобы
не предлагать повторно то, что уже не сработало.

`scripts/evaluate_memory.py` проверяет два искусственных набора среди 200 отвлекающих
фактов и возвращает ошибку ниже порога: `memory_eval.json` (общие слова, hit@5 = 1.0) и
`memory_eval_forms.json` (разные формы слов и близкие отвлекающие факты; было 0.3 при
поиске по словам, стало 0.9, промах — «учиться» / «учится», основа «уч» слишком короткая).
Облачные модели не вызываются; истинность сгенерированного ответа этим не измеряется.

quality_feedback хранит одну актуальную оценку ответа/задания: helpful, unhelpful,
correction. Повтор обновляет запись. `/api/metrics.quality` показывает оценки,
статусы заданий, недоставленные уведомления и неопределённые вызовы. UI отделяет
объём обработки данных от качества помощи. Оценка correction сама не меняет
память: исправление нужно сообщить в чате.

## Проверки

```bash
QT_QPA_PLATFORM=offscreen .venv/bin/python -m unittest discover -s tests -v
.venv/bin/python scripts/evaluate_memory.py
.venv/bin/python -m compileall -q ubermensch tests
git diff --check
```

Используются искусственные данные, временные каталоги, реальный небольшой архив
7-Zip и Qt без подключения к KDE. Живые Telegram/Gmail/Claude и установленный
сеанс Plasma не проверяются. CI повторяет проверки на Python 3.14;
pyproject.toml описывает пакет и зависимости.
