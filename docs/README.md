# Документация разработчика Übermensch

Übermensch — личный помощник одного владельца. Пользовательское имя — Аня;
`anya.exe` — название персонажа и интерфейса, а не отдельная собранная программа.
Сейчас приложение работает как несколько Python-процессов на Linux (KDE Plasma,
Wayland) с одним
ядром и одной SQLite-базой. Целевой масштаб — один владелец с несколькими
устройствами. Удалённые исполнители, синхронизация устройств и мобильный клиент
пока не реализованы.

Документы описывают исходники в этой рабочей копии, включая общий API инструментов
и резервный цикл OpenAI. Дата сверки: **15 октября 2026 года**. Это описание
реализации, а не подтверждение того, что работающий фоновый процесс уже перезапущен
на этой версии.

## С чего начать

1. Прочитать [руководство разработчика](DEVELOPMENT.md): устройство проекта,
   границы компонентов, последовательность освоения и рецепты изменений.
2. Подготовить окружение по [конфигурации и запуску](CONFIGURATION.md), затем
   выполнить [изолированные проверки](TESTING.md). Полный запуск включает сбор
   локальных данных; для первого знакомства он не нужен.
3. Для своей задачи открыть соответствующий контракт: [HTTP и SSE](API.md),
   [SQLite и хранилища](DATA_MODEL.md), [ИИ и инструменты](AI_RUNTIME.md),
   [фоновые процессы](BACKGROUND.md), [клиенты](CLIENTS.md).
4. Перед архитектурным изменением прочитать [ограничения и технический долг](LIMITATIONS.md)
   и [направление развития](EVOLUTION.md).

## Как читать в зависимости от задачи

| Задача | Сначала читать | Затем открыть код |
|---|---|---|
| Добавить инструмент | AI_RUNTIME, SECURITY, TESTING | `capabilities/`, `runtime/`, `tools.py` |
| Исправить переключение ИИ | AI_RUNTIME, LIMITATIONS | `runtime/router.py`, `brain.py`, `openai_brain.py` |
| Изменить задачи или память | DATA_MODEL, API | `store.py`, `assistant.py`, `core.py` |
| Подключить источник данных | BACKGROUND, DATA_MODEL | `collectors/`, `analysis.py` |
| Изменить маскота или виджет задач | CLIENTS, API | `desktop/`, `plasmoid/` |
| Сделать клиент для телефона | API, SECURITY, EVOLUTION | Сначала решить аутентификацию устройств и доставку событий |
| Разобраться с папкой данных и резервными копиями | DATA_MODEL, OPERATIONS | `config.py`, `maintenance.py` |

## Правила актуальности

- Источник истины для исполняемого поведения — код и воспроизводимая проверка.
  Проектируемые возможности явно помечаются как планы.
- Новые маршруты отражаются в API, инструменты — в AI_RUNTIME, миграции — в
  DATA_MODEL, параметры — в CONFIGURATION и при необходимости `.env.example`.
- Документация не содержит реальных токенов, содержимого личных переписок и
  выгрузок базы. Примеры используют вымышленные данные.
- При изменении гарантий повторного выполнения, подтверждений или доставки
  обновляются также SECURITY и LIMITATIONS.
